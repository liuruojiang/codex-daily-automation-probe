# Step 9: restore a previous workflow run

This draft adds a third isolated checkpoint job to the existing PR regression workflow. It reads the immutable **seed** artifact from the completed step-8 run `39432084491`, rather than the already-restored proof or a newly generated checkpoint. It has no dependency on the current run's save job. No production email code, model credential or paid model call is involved.

The accepted producer is fixed: repository `liuruojiang/codex-daily-automation-probe`, same-repository PR158 on `codex/etf-evidence-cards-step1`, workflow `delivery-regression.yml`, successful completed run attempt1, head `1664a7d3f19ae88c84acb2f7d1d249b01ff5372b`. Its checkout merge commit `2b9feddb5ece6e1844e26451acbc3ef14b83c9f5` must have the expected head and base parents. These two SHAs serve different purposes and are not substituted for each other.

Before downloading, the job fetches the producer run, checkout commit and artifact metadata from GitHub with an actions/contents read token. Artifact ID `12269585268`, exact name `etf-checkpoint-seed-39432084491-1` and ZIP SHA256 `8b43513281f565ea4cf2e4bba48c486f610abf3f56ed7a8065891680400deba8` must match. Expired artifacts, foreign repositories, other attempts, wrong code versions, failed or incomplete producers and mismatched workflow/PR are rejected. `download-artifact@v8` receives the explicit artifact ID, prior run ID and GitHub token; a digest mismatch is an error.

The restore accepts a different producer origin only through this explicit pinned cross-run path. It keeps the original bundle origin and records the new consumer origin separately, refuses same-run use, rejects stale verification metadata, and verifies the full file inventory before replay. The shadow runner still reconstructs and checks its source/configuration/prompt/version context; no compatibility check was weakened. Bundle version1 remains readable. Nested `bundle.json` files now count as ordinary inventory files, closing an accidental extra-file omission in the earlier probe.

Expected proof: six real historical material plans replay identically with zero reservations; the synthetic completed receipt recovers to parsed, while the synthetic missing receipt remains unknown. Both synthetic cases retain one request and 2400 output-token reservations and repeated invocation sends no requests. Origin, hashes, budgets and states appear in `cross-run-proof.json`, uploaded with the restored state and verified source metadata for 30 days. The prior seed artifact is downloaded and mutated only in the disposable consumer workspace; its archive remains unchanged.

Local tests include producer/consumer separation, missing/extra files, changed artifact/commit/run/attempt, expired producer artifact and stale consumer metadata. Cloud run links and actual results are recorded in PR158 once execution finishes.

Limits: this is one explicit prior-run acceptance case using a fixed artifact that will expire, not automatic discovery of a latest checkpoint or production scheduling. Cross-run restoration of real material planning is exercised, but paid-request recovery uses synthetic fault boundaries; no real provider outage or billing accuracy is asserted. There is no email or publication eligibility. Hash inventories and GitHub artifact digests are not an independent signing service.
