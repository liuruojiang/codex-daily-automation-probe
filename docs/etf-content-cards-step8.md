# Step 8: isolated cloud checkpoint transfer

The draft PR's existing delivery-regression workflow now includes two isolated jobs, limited to same-repository PRs on `codex/etf-evidence-cards-step1`. No production workflow, email path, model credential, or paid model request is involved. The jobs have contents/actions read permissions only.

The save job validates the fixed successful production collection run `39347818936`, downloads its `us-etf-allocation-digest` artifact, and builds an offline six-material plan. It also creates two explicitly synthetic fault cases in subprocesses. Each child exits with code 86 after reservation: one after a completed response receipt is durably written but before parsing, the other before any receipt exists. The synthetic transport returns local JSON only and never contacts a provider.

The save job uploads the complete checkpoint bundle, including receipts, source manifest and materials, plus an inventory of file hashes. A second job on a fresh runner downloads that artifact, checks the exact inventory and workflow-run/attempt/commit provenance, and restores it using the production shadow runner. It requires the real offline report to remain identical, the completed synthetic receipt to recover without another request, and the unknown case to retain its reservation and unknown status. A further live-mode invocation with maximum 99 new requests and a forbidden transport must make zero calls because the persisted one-request/2400-output-token budget is already exhausted. The output is `checkpoint-proof.json` and a 30-day artifact.

The inventory detects accidental corruption, missing files, extra files and substituted state during transfer. It is not a cryptographic signature against someone able to replace both the inventory and files. A mismatched workflow origin is rejected before restoration.

This exercises separate runner filesystems and artifact upload/download **within one workflow run**. It does not establish cross-workflow-run restoration, actual provider outage behavior, live billing, automatic production recovery, or email eligibility. Synthetic provider usage fields are synthetic and must not be added to real token accounting. The source selection remains a historical capture, not fresh news. The fixed-source probe is an acceptance experiment for this draft branch; its source artifact can expire and it is not a permanent daily dependency.

Local validation: 41 tests plus 7 subtests passed, covering the checkpoint runner and existing delivery workflow contracts. New tests run real subprocess exits and copy bundles to a new directory; changed and extra files are rejected before recovery. Cloud results are recorded after the jobs complete; source and proof artifacts are the execution evidence.
